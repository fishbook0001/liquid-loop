**核心机制**：
- **零向量召回**（v2.0.1）：默认召回升级为「零向量 tf-idf 余弦 + 实体/数字精确加权 booster」
  - 余弦层与TF-IDF基线逐字节同公式（纯词频标量，非embedding）
  - booster对query数字串/长度≥4 token精确命中fact叠加bonus，补回tfidf余弦因长句稀释稀有关键词而漏召的「含数字/量词query」
  - 全量实测：LoCoMo 0.472→0.492、LongMemEval 0.942→0.948，**零向量超越词频向量基线**
  - 守禁向量红线：纯符号精确匹配 + 词频标量，零embedding、零LLM
- **安全护栏**（v2.0.2）：
  - 灾难性回退护栏StateRegressionGuardError：save()落盘前正对照磁盘全量，传入态<10%则拒绝落盘，根治"部分内存态原子覆盖全量磁盘态"静默失效族
  - undo快照轮转：save()前自动创建state.json快照，保留最近10份（约17M）
  - evidence_ids存在性校验：add_memory默认校验evidence_ids全部存在，防止孤儿记忆（历史根因：marvis fact batch 45条占位记忆引用675条不存在evidence_id，引用完整性仅49.1%）
  - 反绝对化词表检测：40+中英双语过度概括词，警告级只标记不拒绝
  - 可逆副作用底座ReversibleRegistry：记录可回滚操作，支持undo/redo
- **E5同义归并**（v2.0.0）：确定性别名表 + 术语归一化（embedding→嵌入 / vector→向量），零embedding、零LLM推断、纯字符串替换，补零token重叠同义洞

**关键产出**：零向量召回超越基线、安全护栏、引用完整性、反绝对化检测、E5同义归并

## 五、开发方法论特征

### 1. 蒸馏驱动
每个大版本都有外部机制蒸馏：
- Semantica → 治理三件套（state_at/analyze_impact/find_duplicates）
- Palantir → 治理dry-run + Authority Line
- Octomind → 压缩机制
- RobSelf → 召回过滤
- U-OPSD → 共识自检
- PlugMem/Skill1/EvoC2F/RE-TRAC → 程序性记忆层D3
- DeepTutor → 反绝对化词表（m60建议2落地）
- DeepSeek Harness → 可逆副作用底座（#204）

### 2. 学术标杆
- PEEK/SEAL优化来自学术标杆蒸馏
- 注意力增益/重放压力来自神经科学实证（Science论文）
- 所有机制均有A/B验证或基准测试

### 3. 诚实基准
- LiquidReweight基准探针诚实结论：**无增益+187x成本**，不掩盖负结果
- LoCoMo/LongMemEval双真实基准全量测试，抗噪有条件修正
- 基准runner加`liquid_cosine`纯余弦对照列，默认列=余弦+booster

### 4. 红线坚守
- 零向量、零LLM依赖贯穿全程
- WHY_NO_VECTOR.md专门钉死边界（防歧义）
- 澄清禁向量红线边界：TfidfBaseline是外部评测对照，不破机制层红线
- 数据schema版本（0.4.0）与workspace state版本（0.5.1）保持独立（禁区不动，红线#4）

### 5. 快速迭代
- 52天34个版本，平均1.5天一个版本
- 小步快跑，每个版本聚焦1-2个核心变更
- 版本号遵循语义化版本：MAJOR.MINOR.PATCH

### 6. 事故驱动
- 共识误删事故 → v0.9.3多智能体授权原语固化
- 跨锚点误结晶 → v0.6.2 P0修复

## 六、技术债与经验教训

### 已修复的技术债
- ✅ cli.py坏死区（v1.x已修复，当前cli完全正常）
- ✅ 测试缺口（当前199测试全绿，覆盖cli/rar/liquid_reweight/selfspin等）
- ✅ 文档漂移（mesh已删但README仍宣传 → 已更新说明）
- ✅ LEI维度不一致（代码9维文档8维 → 已统一为九维）
- ✅ 版本号不统一（核心库2.0.2/服务2.0.1 → v2.0.3统一）
- ✅ 8790重复进程（两个变一个）

### 经验教训
1. **接地文档需定期更新**：Vera接地文档建立于v1.4.0，到v2.0.1时已严重过时，导致技术债清单系统性偏差
2. **τ必须持久化**：时间动力学的有效迭代计数必须持久化，否则重启归零→强化门控恒真→时间衰减失效
3. **部分态覆盖是静默失效族**：save()必须有灾难性回退护栏，否则部分内存态会原子覆盖全量磁盘态且难以察觉
4. **引用完整性需校验**：add_memory必须校验evidence_ids存在性，否则会产生孤儿记忆
5. **零向量不是零召回**：tf-idf余弦+entity_boost可以超越词频向量基线，禁向量红线不影响召回质量
6. **蒸馏要有验证环节**：外部机制蒸馏后必须有A/B验证或基准测试，不能盲目接入
7. **服务进程需去重**：launchd KeepAlive+手动启动可能导致重复进程，需定期检查
